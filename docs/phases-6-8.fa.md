# فازهای ۶، ۷ و ۸ — استخراج، جریان عامل‌ها و بررسی انسانی

[English](./phases-6-8.md)

## وضعیت واقعی

فازهای ۴ و ۵ با خروجی‌های ارسال‌شده توسط امین تأیید شدند: revision برابر `claimflow-api-00002-klk` با ۱۰۰٪ ترافیک فعال است؛ همان پرونده پس از تغییر revision با یک سند، یک review و چهار audit event باقی مانده و اصل فایل با وضعیت ۲۰۰ و حجم ۵۰ بایت بازیابی شده است.

پیاده‌سازی فازهای ۶ تا ۸ و تست‌های خودکار آماده شده‌اند. اجرای واقعی Gemini روی همین پروژه هنوز باید با دستور آزمون زیر تأیید شود. تست محلی با پاسخ کنترل‌شدهٔ مدل، اثبات دقت خواندن دست‌خط یا دسترسی واقعی Vertex نیست.

## قابلیت‌های اضافه‌شده

| فاز | قابلیت |
|---|---|
| ۶ | ارسال اصل فایل‌ها به Gemini، خروجی JSON کنترل‌شده، evidence، confidence و ثبت مدل و مصرف توکن در صورت دریافت |
| ۷ | جریان شش‌مرحله‌ای با Google ADK و ثبت شروع، موفقیت، شکست و توقف مرحله‌ها |
| ۸ | قواعد قطعی، تشخیص تناقض، اصلاح مستند، بازحساب مسائل و جلوگیری از READY شدن نادرست |

جریان ADK شامل دریافت فایل، کنترل اولیه، استخراج، اعتبارسنجی، خلاصه‌سازی وضعیت و ارجاع به انسان است. این جریان با `Workflow` نسخهٔ ۲ ADK و عامل‌های سفارشی `BaseAgent` اجرا می‌شود. جلسهٔ ADK موقت است؛ اطلاعات پرونده و گزارش مراحل در Firestore ماندگارند.

## محدودیت هزینه و پردازش

هر پرونده حداکثر سه سند، مجموعاً پنج صفحه و ده MiB دارد. هر فایل حداکثر پنج MiB است. یک فراخوانی Gemini برای همهٔ اسناد انجام می‌شود. retry خودکار وجود ندارد؛ سقف خروجی ۸۱۹۲ توکن و مهلت پیش‌فرض مدل ۴۰ ثانیه است.

درخواست هم‌زمان یا تکراری نباید دوباره مدل را فراخوانی کند. پس از خطا، خروجی ساختگی جایگزین نمی‌شود. پرونده برای بررسی انسانی باقی می‌ماند. برای تلاش جدید باید سند را صریحاً تعویض یا پروندهٔ جدیدی ایجاد کرد؛ اجرای جدید می‌تواند هزینه داشته باشد.

پس از قطع اجرای برنامه، دکمهٔ بازیابی می‌تواند اجرای قدیمی‌تر از دو دقیقه را بدون فراخوانی دوبارهٔ مدل به بررسی انسانی منتقل کند. پاسخ دیررس اجازهٔ بازنویسی آن را ندارد.

## بررسی انسانی

- تمام فیلدهای پیشنهادی باید با اصل سند بررسی شوند.
- confidence برآورد مدل است و تضمین صحت نیست؛ نقل‌قول evidence نیز هنوز ادعای مدل است.
- تاریخ نامعتبر یا آینده حتی با Accept معتبر نمی‌شود.
- اختلاف مقادیر میان اسناد به اصلاح همراه با دلیل نیاز دارد.
- برای افزودن فیلد جاافتاده، سند، صفحه و متن پشتیبان لازم است.
- Reject باعث آماده‌شدن خودکار پرونده نمی‌شود.
- پس از اصلاح، قواعد و وضعیت پرونده دوباره محاسبه می‌شوند.
- تعویض سند، فیلدها و مسائل قبلی را نامعتبر می‌کند و پرونده را به DRAFT برمی‌گرداند. اصل سند قدیمی و سابقهٔ review و audit نگه داشته می‌شوند.
- READY فقط به معنای آماده‌بودن اطلاعات پرونده است؛ به معنای پذیرش یا رد خسارت نیست.

## استقرار

پس از merge، dev server قبلی را متوقف کن و در PowerShell اجرا کن:

```powershell
git switch main
git pull origin main
npm ci
.\scripts\deploy-cloud.ps1 -AiMode vertex
```

اسکریپت API مربوط به Vertex را فعال می‌کند، نقش `roles/aiplatform.user` را به همان هویت Runtime می‌دهد و نسخهٔ جدید را خصوصی مستقر می‌کند. کلید دانلودشدنی ساخته نمی‌شود.

مدل پیش‌فرض `gemini-3.5-flash` و محل پردازش مدل `global` است. محل دیتابیس و فایل‌ها همچنان Sydney است، اما endpoint جهانی تضمین نمی‌کند پردازش مدل فقط در استرالیا باشد. همچنان فقط سند مصنوعی استفاده می‌کنیم.

برای هزینهٔ اجرا، حداقل instance صفر و حداکثر یک است؛ حافظه یک GiB و هم‌زمانی چهار درخواست است. این تنظیمات سقف پولی نیستند. برای برگشت به mock از `-AiMode mock` استفاده کن.

## آزمون واقعی

در Terminal اول:

```powershell
gcloud run services proxy claimflow-api --project=claimflow-ai-agents --region=australia-southeast1 --port=8081
```

در Terminal دوم:

```powershell
node scripts/smoke-vertex.mjs http://localhost:8081
```

آزمون یک PDF واقعی ولی مصنوعی در حافظه می‌سازد، آن را آپلود می‌کند و فقط یک بار مدل را فراخوانی می‌کند. نام Maya Rivera، پلاک SYN-482، تاریخ ۲۰۲۶-۰۹-۱۰ و نقل‌قول‌ها با متن سند مقایسه می‌شوند. سپس شش مرحلهٔ ADK و مسیر بررسی → READY → اصلاح تاریخ به آینده → جلوگیری از READY → اصلاح صحیح → READY آزموده می‌شوند. reviewهای آزمون با نام صریح عامل تست مصنوعی ثبت می‌شوند.

خروجی `LIVE_VERTEX_ADK_REVIEW` همراه با `PASS` تأیید زندهٔ این مسیر است. آزمون قدیمی `smoke.mjs` مخصوص mock است.

تست نهایی UI با امین و Behzad شامل تناقض میان دو سند مصنوعی، سند ناخوانا، تکمیل فیلد جاافتاده با evidence، تعویض سند و بررسی audit خواهد بود. سنجش جامع دقت دست‌خط هنوز انجام نشده است.

## محدودیت‌های باقی‌مانده

محیط مشترک آزمایشی با IAM محافظت می‌شود؛ نام reviewer هنوز هویت احرازشدهٔ کاربر داخل برنامه نیست. صف توزیع‌شده و ازسرگیری خودکار اجرای نیمه‌تمام وجود ندارند. کنترل PDF و امضای فایل جایگزین اسکن بدافزار نیست. اطلاعات هر پرونده سقف حجمی دارد و پاک‌سازی خودکار فایل‌های بی‌مرجع هنوز اضافه نشده است. جزئیات و منابع رسمی در نسخهٔ انگلیسی آمده‌اند.
